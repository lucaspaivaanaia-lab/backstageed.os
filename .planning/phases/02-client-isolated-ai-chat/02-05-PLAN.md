<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (checked message ids) → saveKnowledge | Only ids cross; content and ownership are re-verified server-side, never trusted from the client |
| server → Tropicalia upload | Server-only key used to upload the curated file to the correct project |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Elevation of Privilege / Tampering | saveKnowledge | mitigate | Re-resolves client via RLS `.eq("id", clientId).single()` and re-reads message rows via `.eq("client_id", clientId).in("id", ids)` — a message id from another client returns no row; content is never taken from the browser |
| T-2-04 | Information Disclosure | uploadTropicaliaDocument call site | mitigate | Runs only in the `"use server"` action; `TROPICALIA_API_KEY` never reaches the panel |
| T-2-02 | Tampering (curated content) | uploaded .md | accept | Content is PM-curated; one self-contained file per save, no merge/append surface to corrupt |
</threat_model>
