## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser URL → Next.js server component | `?client=` and `?pm=` are fully attacker-controlled strings supplied by whoever types the URL |
| Next.js server → PostgREST filter expression | `.or()` takes a raw, non-parameterized filter STRING — the one place in this phase where user input reaches query syntax rather than a bound value |
| Next.js server → Postgres via `createAdminClient()` | `listPmRoster` / `listEditorRoster` — privileged, display-only roster reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Tampering | `.or("assignee_id.eq.${pmId},media_assignee_id.eq.${pmId}")` in `app/admin/page.tsx` | mitigate | `parseOversightFilters` rejects anything that is not a strict UUID before the value can reach the template literal, so a crafted value cannot inject additional PostgREST filter operators. Enforced by a dedicated injection-payload assertion in `lib/cards/oversight-filters.test.ts`. |
| T-06-07 | Denial of service | malformed `?client=` reaching `.eq("client_id", ...)` as a non-UUID, producing a Postgres `22P02` error and a blank screen | mitigate | Same UUID guard drops the value; the page then renders unfiltered rather than erroring. |
| T-06-08 | Information disclosure | full PM + Editor roster (emails) rendered in the person filter and the workload panel | accept | `/admin/*` is role-gated by `middleware.ts`; `listPmRoster` is already exposed on PM-facing screens today, so this introduces no new disclosure surface. |
