<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `advanceStage` | The caller controls only `cardId`; any completion claim would be untrusted and is therefore never accepted as a parameter |
| browser → `toggleChecklistItem` | `itemId` is attacker-controlled; the item's owning card and client are never supplied by the caller |
| Server Action → Postgres | The snapshot insert and the stage update are two separate round-trips with no transaction available |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Tampering | A caller invoking `advanceStage` directly to skip the checklist gate | mitigate | The gate is re-evaluated inside the action from a server-side re-read of `card_checklist_items` via `isGateBlocked`; the disabled button is a UX affordance, not the boundary |
| T-03-13 | Repudiation | A card leaving revisão interna with no record of who cleared it | mitigate | `completed_by` + `completed_at` written by `toggleChecklistItem` from `auth.getUser()`, never from a client-supplied user id; rendered per item in the card Dialog |
| T-03-14 | Tampering | `toggleChecklistItem` called with an `itemId` belonging to another client's card | mitigate | `card_checklist_items_write_scoped` scopes the UPDATE through `cards.client_id`, so a foreign item id matches zero rows (proved by pgTAP assertions 3 and 4 in Task 1) |
| T-03-15 | Denial of Service (self-inflicted) | A mid-request failure between the snapshot insert and the stage update leaving a card in revisão interna with an empty, vacuously-passing checklist | mitigate | Write ordering is snapshot-first with its error checked before the stage update (03-RESEARCH.md Pitfall 3 option b) — the failure mode is "stuck in place", never "advanced unguarded" |
| T-03-16 | Tampering | A template edit retroactively altering an in-progress card's checklist | mitigate | `card_checklist_items` carries no `template_id`/`template_item_id` FK; rows are copied once at entry (D-04), asserted by the Task 1 grep gate |
| T-03-17 | Elevation of Privilege | Snapshot table shipped with RLS enabled but no GRANT | mitigate | GRANT ships in 0016 alongside the policies, asserted by the Task 1 grep gate |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed in this plan. If a task turns out to need one, stop and run the Package Legitimacy Gate protocol first. |
