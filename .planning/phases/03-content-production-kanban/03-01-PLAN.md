<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Server Action | Template names, item labels, template ids and client ids arrive as untrusted arguments; Server Actions are directly callable without going through the UI |
| Server Action → Postgres | Writes cross into privileged data; RLS is the last line, the app-layer role check is the primary gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | `lib/actions/checklist-templates.ts` — a PM invoking a template write action directly | mitigate | Every exported action opens with the `profiles.status === "approved" && profile.role === "admin"` check before any write, and `checklist_templates_admin_write` / `checklist_template_items_admin_write` RLS policies reject the write independently (proved by pgTAP assertions 2 and 3 in Task 1) |
