<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated PM → Server Action | The PM is authenticated but untrusted with respect to *which* clientId/userId they submit; middleware only proves role='pm' for the `/pm/*` path prefix, never per-resource assignment. |
| Server Action → service-role admin client | createAdminClient() bypasses RLS entirely; every argument reaching it must already be authorized at the application layer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | createClientLogin (actions.ts) | mitigate | assertCallerManagesClient() enforces is_admin() OR clientId ∈ pm_assigned_clients() via the RLS-scoped client BEFORE createAdminClient()/auth.admin.createUser; proven by isClientActionAuthorized negative test. |
| T-05-02 | Tampering / IDOR | deactivateClientAccess (actions.ts) | mitigate | Require explicit clientId, authorize the caller for it, then verify userId === findActiveClientLogin(clientId) via isActiveLoginMatch before auth.admin.updateUserById; rejects arbitrary/guessed UUIDs. |
| T-05-03 | Information Disclosure | findActiveClientLogin (actions.ts) | mitigate | Callers reach it only after assertCallerManagesClient in the write paths; WR-01 fixed so a query error is logged and fails closed (returns null) rather than silently masking state. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | This plan adds NO packages (uses Node 24's built-in test runner). No install task, no supply-chain surface introduced. |
</threat_model>
