Trigger contract (RESEARCH.md Pattern 2): handle_new_user() reads raw_user_meta_data->>'role' | 'client_id' | 'must_change_password' and inserts a profiles row (including new.email into profiles.email). PM self-signup passes { role: 'pm' } -> status defaults to 'pending'.

Column-immutability contract (Blocker fix): Postgres RLS is row-granular, NOT column-granular — a "user updates own row" policy cannot stop a PM from setting role='admin'/status='approved' on themselves. A BEFORE UPDATE trigger is the standard Postgres mechanism for column-level immutability. prevent_profile_privilege_escalation() rejects any UPDATE that changes role or status unless public.is_admin() is true.

RLS helpers (RESEARCH.md Pattern 4): public.is_admin() and public.pm_assigned_clients(), both `language plpgsql`, `stable`, `security definer`, `set search_path = ''`.
