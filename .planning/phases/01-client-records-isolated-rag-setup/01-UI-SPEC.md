## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside chips/badges |
| sm | 8px | Compact spacing: chip internal padding, table cell inline gaps |
| md | 16px | Default form field spacing (`gap-4`, matches existing `/signup`), card content padding |
| lg | 24px | Section padding within a page (`px-6`, matches existing `Card`/`CardContent`) |
| xl | 32px | Gaps between major form sections (briefing fields group vs. PM-assignment group) |
| 2xl | 48px | Space above/below the client list's empty-state illustration/copy block |
| 3xl | 64px | Page-level top padding (`py-8`+) for list/form pages inside the content container |

Exceptions: Icon-only remove buttons on chips (content-pillar tags, PM-assignment tags) use a 44×44px minimum touch target achieved via padding around a 16px icon glyph — the icon itself stays on-scale; the touch target is an accessibility padding exception, not a break of the 4px-multiple rule.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 14px | 500 (medium) | 1 (leading-none) |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

**Phase weight budget: 400 (regular) + 600 (semibold)** — the two weights this phase introduces for new page content (body copy, page/section headings, form section titles). Note: the pre-existing shadcn primitives `Label`, `Button`, `Badge`, and `Table` header cells ship with a built-in 500 (medium) weight — that is inherited component-library styling, not a new choice made by this phase, and is not counted against the 2-weight budget. Do not override it.

Usage mapping for this phase:
- **Body (14px/400/1.5)**: table cell text, card descriptions, briefing textarea content, helper/error text
- **Label (14px/500/1, shadcn default)**: form field labels, table column headers
- **Heading (20px/600/1.2)**: section titles inside pages (e.g. "Briefing estratégico", "PMs atribuídos") and `CardTitle` overrides where a page needs a stronger title than the shadcn default
- **Display (28px/600/1.2)**: page-level `<h1>` — "Clientes" (list page), "Novo cliente" / "{client name}" (detail/edit page)

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` ≈ `#FFFFFF` (`--background`) | Page background, form canvas |
| Secondary (30%) | `oklch(0.97 0 0)` ≈ `#F5F5F5` (`--card` / `--muted` / `--secondary`) | Card surfaces, table row hover, dialog surfaces, chip background |
| Accent (10%) | `oklch(0.205 0 0)` ≈ `#262626` (`--primary`) | Reserved for: primary CTA buttons only — "Criar cliente", "Salvar briefing", "Adicionar PM", "Tentar novamente" (RAG retry) — plus the default focus ring. **Not** used for status badges (RAG/briefing status use neutral badge variants + icon, not color, per below). |
| Destructive | `oklch(0.577 0.245 27.325)` ≈ `#DC4C3F` (`--destructive`) | Destructive actions only — validation error text/backgrounds (matches existing `/signup` pattern). No irreversible/destructive user action exists inside this phase's own scope (see Copywriting Contract note); reserved for future reuse. |

Accent reserved for: primary CTA buttons (`Criar cliente`, `Salvar briefing`, `Adicionar PM`, `Tentar novamente`) and default focus/active ring — nothing else.

**Status signaling (RAG status, briefing status — D-14) deliberately does NOT introduce a third semantic hue.** This app's existing palette is pure zero-chroma neutral + one destructive red; adding amber/green status colors would break that discipline. Instead:
- **RAG pronto**: `Badge` `variant="secondary"` + `CheckCircle2` (lucide) icon + text "Pronto"
- **RAG pendente**: `Badge` `variant="outline"` + `Clock` (lucide) icon + text "Pendente" (covers both D-08 retry-needed and D-11 key-absent cases — visually identical; the retry button's presence/absence is what differs, per Copywriting Contract below)
- **Briefing vazio**: `Badge` `variant="outline"` + text "Vazio"
- **Briefing preenchido**: `Badge` `variant="secondary"` + text "Preenchido"

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Criar cliente (client-list page header button + empty-state button) |
| Secondary CTA — briefing save | Salvar briefing |
| Secondary CTA — PM assignment | Adicionar PM |
| Secondary CTA — RAG retry | Tentar novamente (only shown for D-08 case: key present, call failed — never shown for D-11 key-absent case) |
| Empty state heading | Nenhum cliente cadastrado ainda |
| Empty state body | Crie o primeiro cliente para organizar produção de conteúdo e RAG isolado por cliente. (paired with the Primary CTA button) |
| Error — RAG provisioning failed (D-08, key present) | Não foi possível provisionar o projeto Tropicalia agora. O cliente foi criado normalmente — tente novamente quando quiser. (shown next to the "Pendente" badge, paired with the "Tentar novamente" button) |
| Error — RAG key absent (D-11) | RAG setup pendente. (badge + this short label only — no retry button, no elaboration, per D-11's silent-skip behavior) |
| Error — form validation | {Campo} inválido. / {Campo} é obrigatório. — reuses the exact pattern already established in `/signup` (e.g. "E-mail inválido.", "A senha deve ter no mínimo 8 caracteres.") |
| Error — server/network failure on save | Não foi possível salvar as alterações. Verifique sua conexão e tente novamente. |
| Destructive confirmation | None in this phase's scope. Removing a PM-assignment chip or a content-pillar chip is a reversible list edit (re-addable in one click) — no confirmation dialog, per shadcn's low-friction tag-removal convention. Client *deactivation* (a genuinely destructive, confirmation-worthy action) is explicitly out of scope — deferred to Phase 5 (AUTH-11). |
