<objective>
Abandon the 4 fixed strategic-briefing columns (`objective`/`tone_of_voice`/`target_audience`/`content_pillars`) on `public.clients` in favor of one free-text Markdown column, letting the AI propose its own document structure per client instead of filling fixed fields. This is P2 of the 2026-08-05 Juliano action plan, direction "b" -- explicitly chosen by the user over "expand/improve the fixed categories" (direction "a").

Every current client row is confirmed test/fake data (user decision, 2026-08-11) -- **no backfill logic is needed**. The migration drops the 4 old columns and adds one new `briefing text` column; client ROWS are untouched, only the briefing content itself is discarded and starts empty again.

Purpose: remove the rigidity of 4 pre-defined categories so the AI (and the human reviewing its proposal) can structure a client's strategic context however actually fits that client's real material, while keeping every existing safety property (RLS boundary, "AI proposes, human confirms" pattern, client-isolation anchor in the chat prompt) exactly as strict as today.

Output: migration `0027_clients_briefing_text.sql`, a single-field `briefingSchema`, `updateBriefing`/`autofillBriefingFromFiles` rewritten around one Markdown string, `assemble-prompt.ts`'s `briefingBlock` collapsed to one labeled block, every read-site (`app/pm/clients/page.tsx`, `app/pm/clients/[id]/page.tsx`, `app/admin/clients/page.tsx`, `app/admin/clients/[id]/page.tsx`, `app/api/chat/route.ts`) updated to select/render the new shape, and `client-detail-form.tsx`'s 3-textarea-plus-pillar-chips UI replaced with one large `Textarea`.

**Explicitly NOT touched, confirmed unnecessary by research:** `lib/ai/extraction-prompt.ts` (never receives/renders briefing fields -- only `clientName`/`clientTag`/`files`/`sharedFiles`/`instruction`), `lib/ai/structured-extraction.ts` (`inputSchema` is already a generic `Record<string, unknown>` parameter -- a 1-property JSON Schema is a normal valid input, no engine change needed), and `components/clients/client-files-section.tsx` (it imports `type { BriefingInput }` purely to type its own `onBriefingAutofilled?: (briefing: BriefingInput) => void` prop signature -- it never destructures individual fields off `briefing`, so the type changing shape automatically via `z.infer` requires zero source edits there). Do not add work to these three files.
</objective>
