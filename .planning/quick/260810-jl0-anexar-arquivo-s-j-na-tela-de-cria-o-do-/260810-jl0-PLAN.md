<baseline>
- `uploadClientFile` (lib/actions/client-files.ts) does a read-then-insert `FILE_LIMIT` count check against `client_files` — this is exactly why `client-files-section.tsx`'s existing batch loop is strictly SEQUENTIAL (never `Promise.all`). The new client-creation flow must copy that same discipline: concurrent calls could all read the same pre-insert count and blow past `FILE_LIMIT` (currently 20, `lib/client-files/limit.ts`).
- `autofillBriefingFromFiles` NEVER writes anything — it returns a proposal ONLY, persisting nothing to the database on its own. The existing consumer (`client-files-section.tsx`) applies the proposal to an ALREADY-MOUNTED briefing form via an `onBriefingAutofilled` callback bubbled up to `ClientDetailForm`. This quick task's call site (`client-create-form.tsx`) has no such mounted form to apply the proposal to — the browser navigates to the new client's detail page immediately after — so the autofill call's returned `briefing` proposal is necessarily DISCARDED here; only its side-effect-free AI call happens, matching the literal instruction ("same duo of calls, same order") without inventing new cross-page state-passing plumbing, which is out of scope (this task only touches `client-create-form.tsx`, never `client-detail-form.tsx`).
- `generateChecklistDraftFromFiles`, in contrast, DOES persist (writes/updates a `checklist_templates` row with `status='draft'`, `owner_client_id=clientId`) — so its effect IS visible on the new client's detail page immediately after redirect, with no further action needed.

**`client-files-section.tsx`'s `handleUpload` — the EXACT sequential-loop + autofill + checklist-draft pattern to replicate (lines 87-163), reuse this shape verbatim, adapted to a `File[]` state input instead of a submitted `FormData`:**
```tsx
  function handleUpload(formData: FormData) {
    setUploadError(null);
    startUploadTransition(async () => {
      const picked = formData
        .getAll("file")
        .filter((value): value is File => value instanceof File && value.size > 0);

      if (picked.length === 0) {
        setUploadError("Selecione ao menos um arquivo para enviar.");
        return;
      }

      const { accepted, skipped } = splitBySlots(picked, files.length);

      // Loop sequencial obrigatório — NUNCA disparar os uploads em
      // paralelo: uploadClientFile faz read-then-insert do contador de
      // arquivos para checar atFileLimit no banco, então chamadas
      // concorrentes poderiam todas ler o mesmo count pré-insert e
      // ultrapassar o teto de FILE_LIMIT (T-dkr-02).
      const outcomes: UploadOutcome[] = [];
      for (let i = 0; i < accepted.length; i++) {
        const file = accepted[i];
        setProgress({ done: i, total: accepted.length });
        const fd = new FormData();
        fd.append("file", file);
        const result = await uploadClientFile(clientId, fd);
        outcomes.push(
          "error" in result
            ? { filename: file.name, error: result.error }
            : { filename: file.name }
        );
        setProgress({ done: i + 1, total: accepted.length });
      }

      const { successCount, message } = summarizeUploadOutcomes(
        outcomes,
        skipped.map((file) => file.name)
      );
      setUploadError(message);

      if (successCount > 0) {
        if (fileInputRef.current) fileInputRef.current.value = "";
        setSelectedNames([]);
        setFiles(await listClientFiles(clientId));

        const autofill = await autofillBriefingFromFiles(clientId);
        if ("success" in autofill) {
          onBriefingAutofilled?.(autofill.briefing);
          toast.success(BRIEFING_AUTOFILLED_TOAST);
        }

        onChecklistGenerating?.(true);
        const draftResult = await generateChecklistDraftFromFiles(clientId);
        onChecklistGenerating?.(false);
        if ("success" in draftResult) {
          router.refresh();
        }
      }

      setProgress(null);
    });
  }
```
