<objective>
Repensar como a IA participa do ciclo de checklist do cliente, em duas frentes decididas em `260808-ci5-CONTEXT.md` (raised by the developer during Phase 3 wave 9's checkpoint, 2026-08-08):

1. **Geração automática do checklist.** Hoje o Admin precisa clicar em "Gerar/Atualizar checklist com IA" (P0 pivot 2026-08-04) depois que o cliente já existe. A partir deste plano, o mesmo gatilho que já dispara o autofill do briefing — cada upload bem-sucedido de `client_files` — também gera/atualiza automaticamente um checklist **rascunho** para aquele cliente, sem exigir clique algum. **Tanto PM quanto Admin** podem revisar/editar e **confirmar** esse rascunho (a maior mudança de escopo desta feature: abre `checklist_templates` para escrita por PM, estritamente escopada ao(s) cliente(s) daquele PM via `pm_assigned_clients()` — nunca a templates da biblioteca compartilhada, que seguem Admin-only). O rascunho só vira o checklist ATIVO do cliente (o que efetivamente gate-ia `revisao_interna` via `snapshotChecklistForCard`) no momento da confirmação — nunca antes, silenciosamente.

2. **Autocorreção do rascunho do post.** "Revalidar com IA" (também do P0 pivot) hoje é só consultivo. A partir deste plano, ao identificar itens que não passam, a IA reescreve automaticamente o texto do rascunho (`cards.description`) na mesma chamada — sem pedir confirmação antes. Isto **supersede D-06 apenas para o campo `description`** ("D-06-amendment", CONTEXT.md) — o gate de CHK-03 (PM confere manualmente cada item antes de avançar) continua absolutamente intacto: esta mudança nunca toca `card_checklist_items`, nunca chama `advanceStage`/`moveCard`, e nunca abre um caminho de auto-avanço.

Purpose: fechar o loop levantado no checkpoint de wave 9 — IA proativa na geração do checklist e na correção do conteúdo, sem regredir nenhuma garantia de segurança/gate já existente.
Output: uma migração + teste pgTAP (RLS owner-scoped), quatro novas Server Actions em `lib/actions/checklist-templates.ts`, `validateCardAgainstChecklist` reescrito para devolver/persistir `revisedDescription`, e a UI de `/admin/clients/[id]` + `/pm/clients/[id]` + `/pm/board` atualizada para os dois fluxos.
</objective>

**Migration `0023_checklist_templates_owner_scoping.sql` — exact body to ship:**

```sql
alter table public.checklist_templates
  add column status text not null default 'confirmed'
    check (status in ('draft', 'confirmed')),
  add column owner_client_id uuid references public.clients(id) on delete cascade;

create policy "checklist_templates_owner_write"
on public.checklist_templates
for all
to authenticated
using (
  owner_client_id is not null
  and (
    (select public.is_admin())
    or owner_client_id in (select public.pm_assigned_clients())
  )
)
with check (
  owner_client_id is not null
  and (
    (select public.is_admin())
    or owner_client_id in (select public.pm_assigned_clients())
  )
);

create policy "checklist_template_items_owner_write"
on public.checklist_template_items
for all
to authenticated
using (
  exists (
    select 1
    from public.checklist_templates t
    where t.id = checklist_template_items.template_id
      and t.owner_client_id is not null
      and (
        (select public.is_admin())
        or t.owner_client_id in (select public.pm_assigned_clients())
      )
  )
)
with check (
  exists (
    select 1
    from public.checklist_templates t
    where t.id = checklist_template_items.template_id
      and t.owner_client_id is not null
      and (
        (select public.is_admin())
        or t.owner_client_id in (select public.pm_assigned_clients())
      )
  )
);
```

No new `grant` statements — `0013_checklist_templates.sql` already granted `select, insert, update, delete on public.checklist_templates/checklist_template_items to authenticated`; RLS policies are OR'd per command, so this migration only ADDS a second permissive write path scoped to `owner_client_id`. The existing `checklist_templates_admin_write` / `checklist_template_items_admin_write` policies (0013) are untouched and remain the ONLY write path for shared/library rows (`owner_client_id is null`) — CHK-01's reusable-template model for those rows does not change.
