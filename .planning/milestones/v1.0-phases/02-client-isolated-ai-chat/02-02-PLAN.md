<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| retrieved chunks / message content → system prompt | Untrusted-ish text (curated by PM, but injected into the model context) crosses into prompt assembly |
| browser request body → zod schema | Raw JSON crosses into typed, validated input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering | assembleSystemPrompt | mitigate | Function takes a single client's briefing + chunks by value; unit test asserts a second client's data never appears — leakage is impossible in the pure layer |
| T-2-02 | Tampering (prompt injection) | assembleSystemPrompt | accept | v1 content is PM-curated; low-cost habit: place system instructions AFTER retrieved content so injected text is less able to override them |
| T-2-06 | Tampering (input) | validation/chat.ts | mitigate | zod validates clientId (uuid), content (1..4000), messageIds (uuid[]) before any downstream use |
</threat_model>
